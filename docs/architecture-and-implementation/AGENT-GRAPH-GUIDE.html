accept() locks the conversation row inside a short SQL transaction, handles duplicate request IDs/active turns, creates the turn, and claims a lease generation.

Step details · C

The graph does not run once

It cycles model → tool → model until the model stops requesting tools. Then the graph finalizes; the service persists the final turn.

Three kinds of persistence are shown separately: checkpoint, completed tool result, and user-facing conversation turn.

01 · Invoke

LangGraph begins with the new state and config. The conversation thread_id identifies its checkpoint stream.

Sync durability saves graph progress as it advances.

Source

invoke · service.ts:230

02 · Model node

Check guard, reserve a model attempt, stream model output, append assistant message, and queue any tool calls.

No tool calls route to finalization. Calls route to the tool node.

Source

model node · graph.ts:41model stream · model.ts:43

03 · Tool node

Take one pending call. Reuse a saved matching result or validate and dispatch the allowlisted tool. Save result, evidence, and tool message to graph state.

After pending calls are handled, the graph goes back to the model with their results.

Source

tool node · graph.ts:62dispatcher · dispatch.ts:19

04 · Finalize

Require a non-empty answer, validate evidence/citations, mark state done, and return graph result.

Service then updates the app-facing conversation/turn record.

Source

finalize node · graph.ts:177

Persistence A · Graph checkpoint

PostgresSaver stores graph state. FencedPostgresSaver checks the active lease around checkpoint writes.

Checkpoint = where graph progress was. Not the same as the displayed conversation.

Source

Persistence B · Tool result

Completed tool outputs are also saved in app SQL so resume can reuse a completed call.

This reduces replay but does not guarantee exactly-once execution for in-flight work.

Persistence C · User-facing turn

After graph end, the service saves terminal status and answer to the turn, then emits completion to SSE.

Conversation record = what product surfaces. Checkpoint = internal execution state.
